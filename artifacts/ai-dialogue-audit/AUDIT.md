# “有点乱”AI 对话体验审查

审查日期：2026-08-30

审查视口：390 × 844（iPhone 纵向）

范围：从“今天”进入“有点乱”，完成结构化录入、AI 追问、补充回答、综合建议和本地保存。

## 结论

旧流程不健康。用户填写大量事实、感受、解释、担心和问题后，界面只把内容重新排列并要求保存，没有 AI 回应、关键追问、判断依据或下一步。这会让用户感到“录得越多，得到越少”。证据见 [04-structured-inputs.png](04-structured-inputs.png)。

本轮实现把流程改为一场有边界的现实反思对话：

1. AI 先指出它理解到的具体冲突，并只追问一个会明显改变判断的缺失信息。
2. 用户补充后，AI 给出 2–3 个真正不同的选项，并说明每个选项适合什么情况及其代价。
3. AI 提供一个足够小的下一步和一个事后核验问题。
4. 每轮回答显示引用了用户哪些原话，并把判断写成可修正的假设，而不是事实。
5. 对话默认不保存；用户可选择只在本机保存原始记录和最新结构化综合，完整对话不保存。

## 逐步健康度

1. **入口：健康。** “今天”页保留“有点乱”主入口，主任务清楚。[01-today.png](01-today.png)
2. **事实录入：健康。** 先记录已经发生的事情，避免一开始就把事实与猜测混在一起。[02-fact-entry.png](02-fact-entry.png)
3. **感受和结构化字段：健康。** 用户可以补充感受、自己的解释、担心及最想确认的问题。[03-emotion-selected.png](03-emotion-selected.png)
4. **旧结果：失败。** 大量输入后只得到原样整理和保存动作，没有对话价值。[04-structured-inputs.png](04-structured-inputs.png)
5. **新流程承诺：健康。** 在提交前明确说明“先追问，再比较选项与代价”，避免把保存误认为 AI 服务。[05-new-input-promise.png](05-new-input-promise.png)
6. **AI 同意：健康。** 就地说明发送给 DeepSeek 的字段、不会附带的资料、保存方式和敏感信息限制。[06-ai-consent.png](06-ai-consent.png)
7. **关键追问：健康。** 第一轮只问一个高影响缺口，并展示引用依据。[07-ai-clarifying-question.png](07-ai-clarifying-question.png)
8. **综合与选项：健康。** 补充后给出不同选项、适用条件与代价。[08-ai-synthesis-options.png](08-ai-synthesis-options.png)
9. **行动与核验：健康。** 综合结果包含一个小步行动、核验问题和不确定性边界。[09-ai-synthesis-action.png](09-ai-synthesis-action.png)
10. **保存后回看：健康。** 原始记录与最新 AI 综合一起保存，可在旅程中回看；完整聊天记录不保存。[10-saved-ai-reflection.png](10-saved-ai-reflection.png)

## 可访问性与交互检查

- 主按钮、关闭按钮、底部导航具备可访问性角色和标签。
- AI 新回复使用礼貌级实时区域，读屏不会打断用户当前操作。
- 选中导航暴露 selected 状态；关键动作不只靠颜色表达。
- 浏览器检查未发现运行时错误；仅有 React Native Web 对旧阴影样式的弃用警告。

## 证据边界

- 视觉与主路径测试基于本机 Expo Web 的 iPhone 尺寸模拟，不等于实体 iPhone 的最终键盘、触觉、动态字体和网络表现。
- 截图中的 AI 内容来自符合生产接口契约的本地模拟服务，用于稳定复现交互与状态；后端另有 121 项自动测试验证结构、安全和证据约束。
- Render API 0.2.0 已部署；使用不含个人信息的 QA 内容完成真实 DeepSeek 两轮验证，线上依次返回 `clarify` 与 `synthesis`，HTTP 状态均为 200。
- iOS build 6（EAS build `d6c75166-6fa4-4eda-9505-d16dcf0ab5ae`）已成功上传 App Store Connect。最终仍需在实体 iPhone 上用真实但去身份化的案例验收键盘、网络等待、内容锐度和连续纠正体验。
