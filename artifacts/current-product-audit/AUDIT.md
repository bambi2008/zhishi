# 知时当前产品评估

审查日期：2026-08-30
主审查视口：390 × 844
范围：根目录 Web 入口与当前 Expo / React Native 移动端的首次使用、今日状态、回看、今年、命盘入口。
方式：本机浏览器逐步操作、当前截图取证、DOM/可访问性状态检查、源代码核对、移动端类型检查和 API 自动测试。

## 总体判断

知时已经形成了一个可信的产品方向：现实信息优先，命理只作为可审计的文化线索，AI 只负责把信息翻译成可逆行动。视觉语言统一，空状态解释清楚，今日状态保存后能立即进入回看，基础闭环成立。

当前最需要解决的不是视觉重做，而是产品一致性和闭环完整度：仓库内存在两套相互矛盾的导航与定位；年度对话的前置条件没有真正阻断；主导航复用了滚动位置；“记录了什么”已经有闭环，但“建议是否执行、是否有效”还没有闭环。

## 2026-08-30 修正状态

已完成：默认开发入口切换到 Expo 主产品、旧 Web 明确标为历史原型、无命盘年度对话入口阻断、今天页无命盘文案统一、主导航切页回顶、少于 3 天不展示趋势、顶部入口按钮语义与 44px 触区、每日状态单选组及 `aria-checked`、关键浅色文字对比度提升。修正后截图见 `10-fixed-today.png` 与 `11-fixed-year.png`。

已完成本轮后续扩展：AI 建议卡新增“记录这一步”，可标记待执行 / 进行中 / 已完成 / 未执行，并填写结果与新事实；记录会在“回看”和“设置”中汇总、导出或清除。命盘表单已拆为基础资料与可展开的高级规则层。执行记录仍只保存在本机，不新增服务端持久化。

## 逐步健康度

1. **旧 Web 首页：不健康。** 仍展示五栏导航、静态日期和演示用户，与当前移动端四栏架构冲突。见 `01-home.png`。
2. **移动端今天空状态：基本健康。** 价值主张直接、现实记录与命盘依据分层清楚；但“没有命盘就不生成今日判断”与“无命盘也可依据现实信息对话”的实际能力冲突。见 `02-mobile-today-empty.png`。
3. **回看空状态：健康。** 两类记录的来源和返回入口明确，没有伪造趋势。见 `03-mobile-review-empty.png`。
4. **今年空状态：有风险。** 同一首屏同时给出“和知时讨论今年”和“先建立命盘”，主动作与前置条件冲突。见 `04-mobile-year-empty.png`。
5. **年度对话阻断：不健康。** 缺少命盘时仍展示可编辑输入框和启用的发送按钮，只有点击发送后才报错。见 `05-year-guidance-blocked.png`。
6. **命盘入口：健康。** 首次只呈现日期、时间、地点和精度；时区、经度、真太阳时、换日规则和起运算法收进可展开的“高级规则”。见 `06-bazi-entry.png`。
7. **每日状态记录：基本健康。** 字段克制、说明清楚、触点大小充足；Web 预览中选择状态未暴露为 `aria-selected` / `aria-pressed`，需在实体设备上复核 VoiceOver/TalkBack。见 `07-daily-state-sheet.png`。
8. **今天保存后：健康。** 状态即时回填，现实状态与命盘前置条件仍分层显示。见 `08-today-with-state.png`。
9. **回看保存后：有风险。** 记录闭环成立，但从上一页切换后继承内部滚动偏移，页面从中段开始，标题和上下文消失。见 `09-review-with-state.png`。

## 优先级建议

### P0：先统一产品真相

- 明确 `apps/mobile` 是唯一主产品；根目录 Web 要么同步四栏结构，要么改名为 `legacy-demo` 并停止作为默认 `npm run dev` 入口。
- 删除旧 Web 中的静态人物、静态日期和旧导航，避免对外演示时损害可信度。
- 建立一份单一的信息架构契约：今天 / 回看 / 今年 / 命盘，README、截图、测试和发布流程都围绕它。

### P0：修正命盘前置条件

- 无命盘时，“今年”的唯一主按钮应是“建立命盘”；年度对话卡可以预览能力，但输入框、快捷问题和发送按钮应隐藏或禁用。
- `GuidanceSheet` 的发送按钮禁用条件应包含 `scope === 'year' && !chart`，并给出可读的禁用原因。
- 今天页把文案改为：没有命盘仍可只依据现实信息对话；保存命盘后才加入文化周期线索。

### P1：修复主导航滚动模型

- 不要让三个页面共享同一个 `ScrollView` 偏移。给每个页面独立滚动容器，或在 `view` 变化时明确滚到顶部。
- 如果未来要保留各页位置，应按 tab 分别保存，而不是把上一页偏移带到下一页。

### P1：补齐“建议—执行—结果”闭环（已完成）

- 每次 AI 建议后增加极轻量反馈：状态、结果和新事实，并限制为本机保存。
- 回看页展示最近执行记录；设置页支持导出和清除。
- 少于 3 天数据时不显示平均趋势图，只展示原始记录；数据足够后再出现趋势和变化解释。

### P1：降低首次排盘负担（已完成）

- 第一层只收日期、时间、地点、精度；时区、经度、真太阳时、换日规则、起运算法已收进“高级规则”。
- 提交前用一句话说明默认规则，结果页再提供“为什么这样算”和修改入口。

### P1：补无障碍基础

- 顶部安全与设置 `Pressable` 增加 `accessibilityRole="button"`、明确标签和至少 44 × 44 的触控区域。
- 选择组使用 radio/radiogroup 语义或确保原生端稳定暴露 selected 状态。
- 当前多个小字号颜色在纸张背景上的对比度不足：`#7D817B` 约 3.64:1、`#858981` 约 3.27:1、`#989B94` 约 2.59:1；普通小字号目标至少 4.5:1。
- 用实体 iPhone/Android 验证动态字体、键盘遮挡、焦点顺序和读屏播报；截图不能证明完整 WCAG 合规。

## 建议的成功指标

- 新用户首次进入后 3 分钟内完成一次现实问题对话或状态记录。
- 建议生成后 24–72 小时内的“已尝试”率。
- 已尝试建议中，用户确认“获得新事实 / 更清楚下一步”的比例。
- 无命盘用户完成首次价值体验后，再进入排盘的转化率。
- 年度对话入口的前置条件错误率降为 0。
